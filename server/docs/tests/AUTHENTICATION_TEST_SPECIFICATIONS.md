## ログイン機能のテストケース詳細

### テスト 1: 正しい認証情報でログインできる

**入力:**

-   HTTP メソッド: POST
-   URL: `/login`
-   リクエストデータ:
    -   email: ユーザーのメールアドレス
    -   password: "password"（ファクトリーのデフォルト値）

**期待される出力:**

-   HTTP ステータスコード: 200 OK
-   レスポンスボディ:
    ```json
    {
        "success": true,
        "message": "Login successful.",
        "data": null
    }
    ```
-   認証状態: 認証済み（`$this->assertAuthenticated()`）

**検証ポイント:**

-   正しい認証情報でログインが成功する
-   適切な JSON レスポンスが返される
-   ユーザーが認証状態になる

### テスト 2: Remember Me 機能でログインできる

**入力:**

-   HTTP メソッド: POST
-   URL: `/login`
-   リクエストデータ:
    -   email: ユーザーのメールアドレス
    -   password: "password"
    -   remember: true

**期待される出力:**

-   HTTP ステータスコード: 200 OK
-   レスポンスボディ:
    ```json
    {
        "success": true,
        "message": "Login successful.",
        "data": null
    }
    ```
-   認証状態: 認証済み

**検証ポイント:**

-   Remember Me オプション付きでログインが成功する
-   セッションが適切に管理される

## 認証失敗のテストケース詳細

### テスト 3: 存在しないメールアドレスではログインできない

**入力:**

-   HTTP メソッド: POST
-   URL: `/login`
-   リクエストデータ:
    -   email: "invalid@example.com"
    -   password: "password"

**期待される出力:**

-   HTTP ステータスコード: 422 Unprocessable Entity
-   レスポンスボディ: バリデーションエラー
-   認証状態: 未認証（`$this->assertGuest()`）

**検証ポイント:**

-   存在しないメールアドレスでのログインが失敗する
-   適切なバリデーションエラーが返される
-   ユーザーが認証状態にならない

### テスト 4: 間違ったパスワードではログインできない

**入力:**

-   HTTP メソッド: POST
-   URL: `/login`
-   リクエストデータ:
    -   email: ユーザーのメールアドレス
    -   password: "wrong-password"

**期待される出力:**

-   HTTP ステータスコード: 422 Unprocessable Entity
-   レスポンスボディ: バリデーションエラー
-   認証状態: 未認証

**検証ポイント:**

-   間違ったパスワードでのログインが失敗する
-   セキュリティ上の適切なエラーメッセージが返される

### テスト 5: 認証情報が不足している場合はログインできない

**入力:**

-   HTTP メソッド: POST
-   URL: `/login`
-   リクエストデータ: 空の配列

**期待される出力:**

-   HTTP ステータスコード: 422 Unprocessable Entity
-   レスポンスボディ: バリデーションエラー（email, password 両方）

**検証ポイント:**

-   必須フィールドのバリデーションが適切に動作する

### テスト 6: 無効なメール形式ではログインできない

**入力:**

-   HTTP メソッド: POST
-   URL: `/login`
-   リクエストデータ:

## セキュリティ機能のテストケース詳細

### テスト 9: ログイン試行回数の制限が適用される

**入力:**

-   HTTP メソッド: POST
-   URL: `/login`
-   リクエストデータ: 間違ったパスワード
-   実行回数: 6 回（5 回失敗後の 6 回目）

**期待される出力:**

-   1-5 回目: 422 Unprocessable Entity
-   6 回目: 429 Too Many Requests

**検証ポイント:**

-   レート制限が適切に適用される
-   セキュリティ攻撃（ブルートフォース攻撃）が防止される
-   制限回数（5 回）が正しく設定されている

### テスト 10: ログイン成功時にレート制限がクリアされる

**入力:**

-   HTTP メソッド: POST
-   URL: `/login`
-   実行順序:
    1. 2 回の失敗したログイン試行
    2. 1 回の成功したログイン
    3. 再度の失敗したログイン試行

**期待される出力:**

-   1-2 回目: 422 Unprocessable Entity
-   3 回目: 200 OK（成功）
-   4 回目: 422 Unprocessable Entity（レート制限なし）

**検証ポイント:**

-   ログイン成功時にレート制限がリセットされる
-   セキュリティとユーザビリティのバランスが保たれる

### テスト 11: ログイン成功時にセッションが再生成される

**入力:**

-   HTTP メソッド: POST
-   URL: `/login`
-   リクエストデータ: 正しい認証情報

**期待される出力:**

-   HTTP ステータスコード: 200 OK
-   セッション ID とトークンが異なる値

**検証ポイント:**

-   セッションフィクセーション攻撃が防止される
-   セキュリティが適切に強化される

### テスト 12: ログアウト時にセッションが無効化される

**入力:**

-   HTTP メソッド: POST
-   URL: `/logout`
-   認証状態: 認証済みユーザー

**期待される出力:**

-   HTTP ステータスコード: 200 OK
-   セッション情報がクリアされる

**検証ポイント:**

-   ログアウト後にセッションが完全に無効化される
-   セキュリティが適切に保たれる

## テスト実行方法

### Sail 環境での実行

```bash
cd server
chmod +x tests/sh/test-logging.sh
./tests/sh/test-logging.sh
```

### 認証テストのみ実行

```bash
# 特定のテストファイルのみ実行
./vendor/bin/sail artisan test tests/Feature/Auth/AuthenticationTest.php

# 認証関連のテストのみ実行
./vendor/bin/sail artisan test --filter="AuthenticationTest"
```

```bash
# 特定のテストケースのみ実行
./vendor/bin/sail artisan test --filter="正しい認証情報でログインできる"
```
