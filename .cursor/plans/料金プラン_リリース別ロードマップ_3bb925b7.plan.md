# 料金プラン リリース別ロードマップ

## 基本方針

元の計画（[ai読み込み・公開機能プラン](c:\Users\nanoha.cursor\plans\ai読み込み・公開機能プラン_2df1e5c5.plan.md)）からの変更点:

- **追加パック** → **買い切りパック**（メインの有料入口に昇格）
- 買い切りは **失効なし**（使い切るまで残る）、ただし **サブスクより割高**
- ファネル: **フリー → 買い切りで試す → 毎月使うならサブスクがお得**
- AI機能の種類に関係なく **1回=1カウント** は変更なし
- 課金単位は **Group（世帯）** のまま
- **内税**（消費税10%込み）
- **Stripe 最低手数料120円** を考慮し、最低商品価格は400円以上に設定

## 損益シミュレーション（内税・Stripe最低手数料120円考慮）

### 前提条件

- Stripe 手数料: 最低120円（3.6%が120円未満の場合）
- サブスク: Stripe Billing 追加 +0.7%（= 120円 + 売上×0.7%）
- 消費税: 売上 × 10/110（内税）
- 機能別原価: Vision=3円, 画像生成=10円, レシピ提案=3円, 献立提案=5円
- **プラン別機能制限あり**（アプローチ1適用）

### 買い切りパック（one-time: Stripe手数料 = max(売上×3.6%, 120円)）

全機能開放。単価が高い（24〜20円/回）ため全機能でも安全:

| 商品                | 売上(税込) | 消費税 | Stripe | AI原価(楽観/最悪) | 手残り(楽観) | 手残り(最悪) | 利益率(楽観/最悪) |
| ------------------- | ---------- | ------ | ------ | ----------------- | ------------ | ------------ | ----------------- |
| ライト 10回 400円   | 400円      | 36円   | 120円  | 30円/100円        | **214円**    | **144円**    | **54%/36%**       |
| バリュー 30回 800円 | 800円      | 73円   | 120円  | 90円/300円        | **517円**    | **307円**    | **65%/38%**       |

### サブスクリプション（recurring: Stripe手数料 = max(売上×3.6%, 120円) + 売上×0.7%）

機能制限により、各プランの最悪ケースが変わる:

| プラン             | 売上    | 固定費(税+Stripe) | 使える機能       | AI原価(楽観/最悪) | 手残り(楽観) | 手残り(最悪) | 利益率(楽観/最悪) |
| ------------------ | ------- | ----------------- | ---------------- | ----------------- | ------------ | ------------ | ----------------- |
| スタンダード 580円 | 580円   | 177円             | Vision+提案(3円) | 90円/90円         | **313円**    | **313円**    | **54%/54%**       |
| プロ 980円         | 980円   | 216円             | +画像生成(10円)  | 150円/500円       | **614円**    | **264円**    | **63%/27%**       |
| プロ+ 1,580円      | 1,580円 | 275円             | +献立提案(5円)   | 300円/1,000円     | **1,005円**  | **305円**    | **64%/19%**       |

### 判定

- **全商品・全シナリオで黒字を確保**（最悪ケースでも赤字なし）
- **スタンダードは利用パターンに関係なく常に 54% の利益率**（機能制限で保護）
- 画像生成原価が将来上昇しても、スタンダード/フリーは影響を受けない
- 1st リリース（Vision のみ 3円/回）では全プラン利益率 50%超え
- **最悪ケースでもライト144円・プロ+305円/月の利益** → 許容可能

## 買い切りパックの設計詳細

### 残高管理

- `groups` テーブルに `ai_credit_balance`（買い切り残高）カラムを追加
- 購入するたびに残高に加算（失効なし）
- 消費順序: **サブスク月間枠 → 買い切り残高** の順で消費

### 消費順序のUX（確定: 消費元の常時表示 + 切り替わり通知）

サブスク枠と買い切り残高の2つのプールがあるため、「なぜか買い切りが減っている」という混乱を防ぐ必要がある。

**方針: 消費元の透明性を UI で担保する**

1. **消費元の常時表示**: AI機能の利用後や残回数表示で、常にどちらの残高から消費されたかを明示する
   - 例: 「サブスク: 残り22/30回 | パック: 8回」
   - どちらが減ったか一目でわかる状態を維持
2. **切り替わり時の1回通知**: サブスク月間枠がゼロになり、買い切り残高からの消費に切り替わったタイミングで通知を1回表示する
   - 例: 「今月のサブスク枠を使い切りました。以降は買い切り残高から消費されます」
   - 毎回ではなく**切り替わり時の1回だけ**（煩わしさを抑える）
3. **毎回の選択は不要**: 消費順序は自動（サブスク → 買い切り）のまま。ユーザーに毎回選ばせると操作が煩雑になるため採用しない

### サブスク加入者と買い切りの関係

- サブスク加入者も買い切り購入可能（月間枠を超えた分に使える）
- サブスク解約後も買い切り残高は残る（失効しない）
- サブスク月間枠はリセット、買い切りは減らない

### API パス（命名）

元の `10` / `30` から **スラッグ名** に変更:

- `POST /billing/packs/light` → ライト（10回）
- `POST /billing/packs/value` → バリュー（30回）

### Stripe 商品構成

| Stripe Price              | 種類                | meap 側の対応        |
| ------------------------- | ------------------- | -------------------- |
| `STRIPE_PRICE_STANDARD`   | recurring (monthly) | スタンダードサブスク |
| `STRIPE_PRICE_PACK_LIGHT` | one_time            | 買い切りライト       |
| `STRIPE_PRICE_PACK_VALUE` | one_time            | 買い切りバリュー     |

## コスト管理方針（確定: アプローチ 1+2+3）

「1回=1カウント」のシンプルさを維持しつつ、機能単位での赤字を防ぐ。

### 方針の全体像

| #   | アプローチ             | 内容                                       | コード影響                       |
| --- | ---------------------- | ------------------------------------------ | -------------------------------- |
| 1   | **プラン別機能制限**   | 原価の高い機能を上位プラン限定にする       | 2nd〜でアクセス制御が必要        |
| 2   | **機能別モデル最適化** | 機能ごとにコスパの良いモデルを選定する     | `config/ai.php` のモデル設定拡張 |
| 3   | **原価上限ルール**     | モデル選定時に損益分岐を超えないか確認する | **コード不要（運用ルール）**     |

### アプローチ 1: プラン別機能アクセス

| AI機能                  | 原価目安 | フリー | スタンダード | プロ  | プロ+ | 買い切り |
| ----------------------- | -------- | ------ | ------------ | ----- | ----- | -------- |
| レシピ読み込み (Vision) | 3円      | o      | o            | o     | o     | o        |
| レシピ提案              | 3円      | o      | o            | o     | o     | o        |
| 画像生成                | 10円     | -      | -            | **o** | o     | o        |
| 献立提案                | 5円      | -      | -            | -     | **o** | o        |

- フリー/スタンダードは **原価の安い機能のみ** → どんな使い方でも安全
- 画像生成（高原価）は **プロ以上** に限定
- 買い切りパックは単価が高い（24〜20円/回）ため全機能開放しても余裕あり
- 機能制限により **「プロにすると画像生成が使える」** というアップグレード動線が自然に生まれる

### アプローチ 2: 機能別モデル設定

機能ごとに最適なモデルを選び、`config/ai.php` で管理する:

```php
'models' => [
    'vision'     => env('AI_VISION_MODEL', 'gpt-4o'),
    'suggestion' => env('AI_SUGGESTION_MODEL', '...'),       // 2nd〜
    'image_gen'  => env('AI_IMAGE_GEN_MODEL', '...'),        // 3rd〜
    'meal_plan'  => env('AI_MEAL_PLAN_MODEL', '...'),        // 4th〜
],
```

- プロバイダー切替は `.env` の変更のみで対応可能（既に抽象化済み）
- Gemini への切替で Vision/テキスト原価を 60-80% 削減可能

### アプローチ 3: 原価上限ルール（運用ルール・コード不要）

新しいモデルを採用する際に、以下を確認する:

> **その機能を使えるプランの中で最も損益分岐が低いプランの 70% を原価上限とする**

| プラン       | AI予算(売上-固定費) | 回数  | 損益分岐 | 70%上限 |
| ------------ | ------------------- | ----- | -------- | ------- |
| スタンダード | 403円               | 30回  | 13.4円   | 9.4円   |
| プロ         | 764円               | 50回  | 15.3円   | 10.7円  |
| プロ+        | 1,305円             | 100回 | 13.1円   | 9.2円   |

- 全プラン開放機能（Vision等）: 上限 **9.2円**（Pro+に律速）
- プロ以上限定機能（画像生成等）: 上限 **9.2円**（同上）
- プロ+限定機能（献立提案）: 上限 **9.2円**

### 原価超過時の判断フロー

```
新モデル / 新機能の原価が上限を超える
  → まず安いモデルを探す（アプローチ2）
  → それでも超えるなら上位プラン限定にする（アプローチ1）
  → それでも超えるなら料金を改定する
```
