# PAY.JP 課金 E2E 手順

ブラウザから meap の課金フロー（カード登録・サブスク・パック・履歴表示）を通し確認する手順です。**テストモード**（`pk_test_` / `sk_test_`）で実施してください。

関連:

- [アカウント設定（Phase 0）](PAY.JP_アカウント設定_手順.md)
- [Webhook 手順](PAY.JP_課金_Webhook_手順.md)
- [ステージングと本番公開の方針](ステージングと本番公開_方針.md)

---

## 前提

| 項目                          | 内容                                                                       |
| ----------------------------- | -------------------------------------------------------------------------- |
| ユーザー                      | メール認証済みのアカウント（未認証だと API が 409 になる場合あり）         |
| 環境変数                      | サーバー・フロント双方に PAY.JP キーが設定済み                             |
| Webhook（ローカル）           | `payjp-cli listen --forward-to http://localhost:8001/payjp/webhook` を起動 |
| Webhook（ステージング・本番） | Dashboard の URL が `.../payjp/webhook` で配信 200                         |
| 画面                          | **プラン管理** `/settings/billing`                                         |

---

## テストカード（PAY.JP 公式）

[テストカード一覧](https://docs.pay.jp/v2/guide/developers/testcards) に従い、**将来の有効期限**と **任意の CVC** を入力します。

| 用途             | カード番号                           |
| ---------------- | ------------------------------------ |
| 決済成功（通常） | `4242 4242 4242 4242`（Visa）        |
| その他ブランド   | 公式ドキュメントの成功系番号を使用可 |

ライブモードではテストカードは使えません。本番確認は実カードで少額（例: ライトパック 400 円）を 1 件行い、必要に応じて返金・解約手続きを行ってください。

## シナリオ A: スタンダードプラン開始（カード新規）

1. `/settings/billing` を開く
2. **プランを変更** → スタンダードを選択 → 決済ダイアログでカード情報を入力（4242…）→ 申し込み
3. **期待結果**
   - ダイアログが閉じ、画面が更新される
   - 現在のプランが「スタンダード」
   - 支払い設定にカード下 4 桁（4242）と有効期限
   - AI 利用状況の月間枠がスタンダード上限に近い値（例: 30 回）
   - `payjp-cli` または Dashboard で `subscription.created` 等が **HTTP 200**
   - 請求履歴に初回請求が表示される（日付・説明・金額。領収書 URL はなし）

---

## シナリオ B: 買い切りパック購入

1. フリープラン、またはカード登録済みの状態で `/settings/billing` を開く
2. **買い切りパックを購入** → ライトまたはバリューを選択 → 必要ならカード入力 → 購入
3. **期待結果**
   - 買い切りパック残りが増加（ライト +10 / バリュー +30）
   - 請求履歴に都度課金の行が追加
   - Webhook で charge 関連イベントが 200（パックは Charge API。サブスク更新イベントとは別）

カード未登録の場合は、ダイアログ内でカード登録と同時に課金されます。

---

## シナリオ C: 支払い方法の変更

1. サブスク中、またはカード登録済みで **支払い方法を変更** を押す
2. 別のテストカード（例: `4012 8888 8888 1881`）で **カードを更新**
3. **期待結果**
   - 支払い設定の下 4 桁・ブランドが更新される
   - サブスク状態は維持される

---

## シナリオ D: プラン解約（Grace period）

1. スタンダード契約中に **プランを変更** → フリーへ変更（解約）
2. **期待結果**
   - 解約予定の注記（次回更新日まで利用可）が表示される
   - 更新日まではスタンダードのまま利用可能
   - Webhook `subscription.updated` / 解約系が 200

詳細仕様はアプリ内 [プラン変更の仕組み](/help/plan-change) を参照。

---

## シナリオ E: 請求履歴・次回請求

1. サブスク契約中に **次回のお支払い予定** に次回更新日と金額が表示される
2. **請求履歴** で月を切り替え、日付・内容・金額のみ表示される（外部請求書リンクはなし）

## うまくいかないとき

| 症状                      | 確認                                                                  |
| ------------------------- | --------------------------------------------------------------------- |
| プランが free のまま      | Webhook 転送 / Dashboard URL / `PAYJP_WEBHOOK_TOKEN`                  |
| 401 Invalid webhook token | Token とヘッダー `X-Payjp-Webhook-Token` の一致                       |
| カードフォームが出ない    | `NEXT_PUBLIC_PAYJP_PUBLIC_KEY`、ブラウザコンソールの payjp.js エラー  |
| API 409                   | メール未認証。認証後に再試行                                          |
| テストカードが拒否される  | test キーと test モードか、ライブモードでテストカードを使っていないか |

Webhook の詳細は [PAY.JP 課金・Webhook 手順](PAY.JP_課金_Webhook_手順.md) のトラブルシュートを参照してください。
