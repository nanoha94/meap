# メンテナンス中画面の表示制御

meap では、サーバー（Laravel）とクライアント（Next.js）の **2 系統**でメンテナンス中画面を制御する。
マイグレーション時の一時停止だけでなく、計画メンテナンスや緊急停止にも対応できる設計になっている。

## 全体像

```
ユーザーのブラウザ
  │
  ├─ Next.js Middleware（proxy.ts）
  │    └─ NEXT_PUBLIC_MAINTENANCE_MODE=true
  │         → 全ルートを /maintenance にリダイレクト（クライアント主導）
  │
  └─ API リクエスト → Laravel
       └─ php artisan down
            → 503 レスポンス
            → クライアントが 503 を検知して /maintenance にリダイレクト
```

| 系統 | 起点 | 制御方法 | 対象範囲 | 主な用途 |
|------|------|----------|----------|----------|
| クライアント主導 | Next.js Middleware | `NEXT_PUBLIC_MAINTENANCE_MODE` | フロント全ルート | 計画メンテナンス・緊急停止 |
| サーバー主導 | Laravel Middleware | `php artisan down` | API レスポンス → クライアント | マイグレーション等のサーバー作業 |

## 系統 1: クライアント主導（NEXT_PUBLIC_MAINTENANCE_MODE）

### 仕組み

Vercel（または Next.js ホスト）の環境変数 `NEXT_PUBLIC_MAINTENANCE_MODE` を `true` にすると、
Next.js Middleware（`proxy.ts`）がすべてのリクエストを `/maintenance` にリダイレクトする。

```
proxy.ts
├─ isMaintenanceModeEnabled()
│    └─ NEXT_PUBLIC_MAINTENANCE_MODE === 'true' を判定
└─ /maintenance と /images/*（ロゴ等の静的アセット）以外 → /maintenance にリダイレクト
```

### 有効化・解除

Vercel ダッシュボード → Settings → Environment Variables で設定する。

| 操作 | 手順 |
|------|------|
| 有効化 | `NEXT_PUBLIC_MAINTENANCE_MODE` を `true` に変更 → 再デプロイ |
| 解除 | `NEXT_PUBLIC_MAINTENANCE_MODE` を `false` に変更 → 再デプロイ |

> **注意**: `NEXT_PUBLIC_` プレフィクスのためビルド時に埋め込まれる。値を変えたら**再デプロイが必要**。

### メンテナンス中に許可されるパス

`proxy.ts` の `isAllowedDuringMaintenance` で制御:

- `/maintenance` — メンテナンスページ本体
- `/images/*` — ロゴ等の静的アセット（メンテナンスページで使用）

### 関連コード

- `client/src/proxy.ts` — Middleware 本体
- `client/.env.example` — 環境変数の定義

## 系統 2: サーバー主導（php artisan down → 503）

### 仕組み

Laravel の `php artisan down` を実行すると、API が 503 (Service Unavailable) を返す。
クライアント側は SSR・CSR それぞれのレイヤーで 503 を検知し、`/maintenance` にリダイレクトする。

```
Laravel（php artisan down）
  │
  └─ 503 レスポンス
       │
       ├─ SSR（apiClient / fetchData）
       │    └─ redirectIfServiceUnavailable() → redirect('/maintenance')
       │
       └─ CSR（axios interceptor）
            └─ 503 検知 → window.location.href = '/maintenance'
```

### 有効化・解除

Railway SSH 内で実行する:

```bash
# メンテナンスモード有効化
php artisan down

# メンテナンスモード解除
php artisan up
```

### メンテナンス中でも許可される API パス

`bootstrap/app.php` の `preventRequestsDuringMaintenance` で制御:

- `/up` — ヘルスチェック（Railway がサービス死活を判定するために必要）
- `square/webhook` — Square からの Webhook（課金処理の取りこぼし防止）

### クライアント側の 503 検知

#### SSR（サーバーコンポーネント）

`fetchData` の戻り値に含まれる `statusCode` を使い、503 を判定してリダイレクトする。

- `redirectIfServiceUnavailable(result)` — 単一の `fetchData` 結果が 503 なら `/maintenance` へ
- `redirectIfAnyServiceUnavailable(...results)` — 複数の `fetchData` 結果のいずれかが 503 なら `/maintenance` へ

使用箇所:

| レイアウト | 関数 |
|-----------|------|
| `(app)/layout.tsx` | `redirectIfAnyServiceUnavailable()` |
| `(auth)/layout.tsx` | `redirectIfServiceUnavailable()` |
| `(auth)/(session)/layout.tsx` | `redirectIfServiceUnavailable()` |

#### CSR（クライアントコンポーネント）

axios の response interceptor で 503 を検知し、`window.location.href` で `/maintenance` に遷移する。
遷移完了まで呼び出し元の `catch` を走らせないよう、解決しない Promise を返す。

```
axiosInstance.interceptors.response.use(
    response => response,
    error => {
        if (error.response?.status === 503 && window.location.pathname !== '/maintenance') {
            window.location.href = '/maintenance';
            return new Promise(() => {});  // 遷移完了まで呼び出し元をブロック
        }
        ...
    }
);
```

### 関連コード

- `server/bootstrap/app.php` — メンテナンス除外パスの設定
- `client/src/lib/apiClient.ts` — SSR 側の 503 検知・リダイレクト
- `client/src/lib/axios.ts` — CSR 側の 503 検知・リダイレクト

## メンテナンスページ

パス: `/maintenance`

| ファイル | 役割 |
|---------|------|
| `client/src/app/maintenance/page.tsx` | メンテナンスページ UI |
| `client/src/app/maintenance/layout.tsx` | メタデータ設定（noindex） |

- ロゴ + 「ただいまメンテナンス中です」メッセージを表示
- `createPrivatePageMetadata` で `robots: noindex` を設定（検索エンジンにインデックスさせない）

## 運用フロー

### 計画メンテナンス（マイグレーション等）の推奨手順

```
1. Vercel: NEXT_PUBLIC_MAINTENANCE_MODE=true → 再デプロイ
   ↓  ユーザーには即座にメンテナンス画面が表示される
2. Railway SSH: php artisan down
   ↓  API も 503 に（二重の安全策）
3. マイグレーション等の作業を実施
4. Railway SSH: php artisan up
   ↓  API 復旧
5. Vercel: NEXT_PUBLIC_MAINTENANCE_MODE=false → 再デプロイ
   ↓  ユーザーに通常画面が表示される
```

> マイグレーションの詳細な手順は [Railway 本番マイグレーション手順](Railway_本番マイグレーション手順.md) を参照。

### 緊急停止（サーバーのみ）

サーバーだけを止める場合は `php artisan down` のみでもクライアントが 503 を検知して `/maintenance` に遷移する。
ただしフロントのルーティング自体は動くため、メンテナンスページから別ページに手動遷移すると一瞬レイアウトが見える可能性がある。
完全に遮断したい場合は `NEXT_PUBLIC_MAINTENANCE_MODE=true` も併用する。

## 設計上の注意点

- **`NEXT_PUBLIC_MAINTENANCE_MODE` はビルド時埋め込み**: 値を変えたら再デプロイが必須。ランタイムでは切り替わらない
- **503 検知は全レイアウトで必要**: 新しいルートグループを追加する場合、そのレイアウトにも `redirectIfServiceUnavailable` を入れること
- **CSR の 503 遷移は `window.location.href`**: Next.js の `router.push` ではなくフルリロードで遷移するため、React の状態はリセットされる
- **ヘルスチェック `/up` は除外必須**: `preventRequestsDuringMaintenance` から除外しないと Railway がサービスダウンと判定する
