# 通知運用ガイドライン

本ドキュメントは、meap における利用規約・プライバシーポリシーの改定、サービス内容の変更等に伴うお客様への通知について、運用基準・通知方法・タイミング等を定めるものである。

利用規約上の通知方法は「当事業者の定める方法」（第15条）と汎用的に規定しているため、本ドキュメントで具体的な運用ルールを定める。

---

## 1. 適用範囲

本ガイドラインは、以下の事象に対するお客様への通知に適用する。

| # | 事象 | 主な根拠条項 |
|---|---|---|
| 1 | サービス内容の変更・追加・廃止 | 利用規約 第12条 |
| 2 | 利用規約の改定 | 利用規約 第13条 |
| 3 | プライバシーポリシーの改定 | プライバシーポリシー 第9項 |
| 4 | サービスの一時停止・中断 | 利用規約 第8条 |
| 5 | 利用制限・登録抹消 | 利用規約 第9条 |

なお、第8条に基づくサービスの一時停止・中断（保守、障害対応等）は規約上「事前通知不要」と定めているため、本ガイドラインによる事前通知の対象外とする（事後共有は推奨）。

---

## 2. 変更の重大性区分

| 区分 | 内容 | 例 |
|---|---|---|
| **A. 軽微** | 誤字・脱字の修正、表現の明瞭化、形式の調整など、お客様の権利義務に実質的影響を与えない改定 | 「ユーザー」→「お客様」の表記統一、リンク修正 |
| **B. 中程度** | 既存条項の運用ルール明確化、新機能追加に伴う規約整備など、お客様の権利義務に影響するがお客様の利益に適合する改定 | 新機能リリースに伴う条項追加、お客様向けの免責範囲縮小 |
| **C. 重要（不利益変更を含む）** | 料金体系の変更、機能廃止、賠償条項の変更、データ取扱いの重要な変更など、お客様に不利益を生じる可能性のある改定 | 無料 → 有料化、サブスクの料金変更、サービス廃止、共有機能の仕様変更 |

判断に迷う場合は **より重大な区分として扱う**（保守的に運用する）。

---

## 3. 重大性別の通知方法・タイミング

| 重大性 | 通知方法 | タイミング |
|---|---|---|
| **A. 軽微** | 規約・ポリシーページの改定日付を更新（および改定履歴セクションがある場合はそこへ追記） | 改定と同時 |
| **B. 中程度** | 上記 ＋ サービス上での告知（実装され次第アプリ内お知らせや公式ブログ等） | 改定と同時または改定の **7日以上前** |
| **C. 重要** | 上記 ＋ **登録メールアドレス宛のメール送信** | 改定の **30日以上前** |

### 3.1 補足

- **C の改定（特にサブスク開始や不利益変更）** では、メール送信は**必須**とする。アプリ内お知らせやブログの実装有無に関わらず、メール送信を行う。
- 重大性の判断基準として「お客様が事前に知らずに変更を受けたら不利益を被るか」を主軸とする。
- 民法 第548条の4 第2項により、**規約変更は「効力発生時期」を定め、事前に周知しなければ効力が生じない**点に留意する。

## 4. 利用可能な通知手段

現状で利用可能な通知手段と、将来的な実装予定を以下に整理する。

| 手段 | 状況 | 用途 |
|---|---|---|
| 規約・ポリシーページの改定日付・履歴更新 | 利用可 | 全レベル共通の最低ライン |
| 登録メールアドレス宛のメール送信 | 基盤利用可（メール認証用 Mailer 流用） | 重要な改定（C） |
| アプリ内お知らせ機能 | **未実装**（将来検討） | 中程度（B）以上で活用予定 |
| 公式ブログ | **未実装**（将来検討） | 中程度（B）以上で活用予定 |
| 公式 SNS（X 等） | **未開設**（将来検討） | 中程度（B）以上で活用予定 |

## 5. 改定履歴の管理

### 5.1 利用規約・プライバシーポリシー
- ページ末尾に **「制定日」** および **「最終改定日」** を明記する。
- 改定履歴セクション（または別ページ）を設け、各改定の日付・概要を記載することが望ましい（将来 `/terms/history` 等の実装を検討）。

### 5.2 メール通知の記録
- 重要な改定（C）でメール送信を行った場合、以下を記録する。
  - 送信日時
  - 送信対象（全お客様 / 特定区分のお客様）
  - 件名・本文（テンプレート ID でもよい）
  - 送信件数および成功・失敗件数
- バッチログ、または別途管理表（Notion 等）に保管する。

## 6. 通知文テンプレート例

### 6.1 軽微な改定（A）
規約・ポリシーページの改定履歴セクションへの記載例。

```
2026-05-15 表記統一（「ユーザー」→「お客様」）
2026-06-10 第7条 第6号 表現の明確化
```

### 6.2 中程度の改定（B）
アプリ内お知らせまたはブログでの告知例。

```
件名: meap 利用規約改定のお知らせ（2026年7月1日施行）

平素より meap をご利用いただき、誠にありがとうございます。
このたび、新機能「○○」の追加に伴い、利用規約を以下の通り改定いたします。

施行日: 2026年7月1日

【主な改定内容】
- 第◯条: ◯◯◯◯◯◯
- 第◯条: ◯◯◯◯◯◯

改定後の利用規約は以下からご確認ください。
https://(meap のドメイン)/terms

今後とも meap をよろしくお願いいたします。
```

### 6.3 重要な改定（C）
メール本文の例。

```
件名: 【重要】meap 利用規約の改定について（2026年8月1日施行）

平素より meap をご利用いただき、誠にありがとうございます。
このたび、利用規約を以下の通り改定いたしますので、ご確認ください。

施行日: 2026年8月1日（本メール送信日から30日以上後の日付）

【主な改定内容】
- 第4条（利用料金）: ○○機能の有料化に伴う料金規定の追加
- 第◯条: ◯◯◯◯◯◯

【お客様への影響】
- ○○機能を継続してご利用いただくには、施行日以降、月額○○円のお支払いが必要となります。
- 既存の登録データには影響ありません。

【ご利用継続を希望されない場合】
施行日までに退会手続をお取りいただくことで、料金が発生することなくご利用を終了いただけます。

改定後の利用規約は以下からご確認ください。
https://(meap のドメイン)/terms

ご不明点等ございましたら、お問い合わせ窓口までご連絡ください。
今後とも meap をよろしくお願いいたします。
```

## 7. 運用フロー

規約・ポリシー改定時の標準フロー。

1. **改定内容と重大性区分を決定**（迷った場合は上位区分で運用）
2. **施行日を決定**（区分 C は最低30日先、B は最低7日先を確保）
3. **改定後の規約・ポリシーページの草稿作成**
4. **必要な通知文の作成**（テンプレートを参照）
5. **施行日の到来をもって規約・ポリシーページを公開**
6. **記録を残す**（改定履歴・メール送信記録）

## 8. 本ガイドラインの改定

本ガイドラインは社内向け運用基準であり、お客様の同意は不要である。運用上の見直しが必要となった場合、本ファイルを直接更新する。
