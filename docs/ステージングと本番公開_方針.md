# ステージングと本番公開の方針

デプロイと一般公開は別です。この文書は、ステージングの保護、本番テストの進め方、DNS / Google 検索の扱いをまとめます。

関連:

- [Railway 本番マイグレーション手順](Railway_本番マイグレーション手順.md)
- [PAY.JP 課金・Webhook 手順](PAY.JP_課金_Webhook_手順.md)
- [PAY.JP 課金 E2E 手順](PAY.JP_課金_E2E_手順.md)

## デプロイとリリース

| 用語         | 意味                                                                   |
| ------------ | ---------------------------------------------------------------------- |
| **デプロイ** | コードをサーバーに載せる。URL が存在する状態になる                     |
| **リリース** | 一般ユーザーが使える状態にする（noindex 解除、告知、PAY.JP live など） |

本番の DNS（`meap-app.com` / `api.meap-app.com`）は **設定済み** です。表向きのリリースには、次を揃える必要があります。

1. Vercel 本番の `NEXT_PUBLIC_BACKEND_URL` が本番 API（`https://api.meap-app.com`）を向いていること
2. 本番の `NEXT_PUBLIC_NOINDEX` を解除し、検索インデックスを許可する
3. PAY.JP を live モードにする（`pk_live_` / `sk_live_`）
4. LP や SNS から `https://meap-app.com` を案内する

公開ページの URL 一覧は `client/src/app/sitemap.ts` に定義しています。noindex 中は `/robots.txt` でクロールされませんが、解除直後から使えます。

## 環境の役割

| 環境                 | URL の例                              | 役割                                                                     |
| -------------------- | ------------------------------------- | ------------------------------------------------------------------------ |
| ステージング         | `dev.meap-app.com` / `dev.api.meap-app.com` | 本番相当の E2E。カスタムドメインあり                                     |
| 本番テスト（非公開） | `*.vercel.app` / `*.up.railway.app`   | 公開前の通し確認。本番ブランドとしては出さない                           |
| 本番（公開）         | `meap-app.com` / `api.meap-app.com`   | 一般公開用。DNS は設定済み。リリース日は noindex 解除・PAY.JP live・告知 |

ステージングのカスタムドメインは **既に DNS 済み** です。Google 検索に出ないのは DNS 未設定ではなく、未リンク・未クロールが主因です。

## DNS の確認方法

DNS 設定済みとは、ホスト名が Vercel / Railway に解決され、HTTPS で応答が返ることです。未設定なら名前解決に失敗するか、別先を向いて 404 などになります。

### 本番

```powershell
nslookup meap-app.com
nslookup api.meap-app.com
```

```powershell
curl.exe -s -o NUL -w "%{http_code}`n" https://meap-app.com/
curl.exe -s -o NUL -w "%{http_code}`n" https://api.meap-app.com/up
```

`200` なら DNS とサーバーまで到達しています。

### ステージング

```powershell
nslookup dev.meap-app.com
nslookup dev.api.meap-app.com
```

名前（`Aliases`）と CNAME / IP が返れば DNS は設定済みです。

確認時の例:

```
Aliases:  dev.meap-app.com
名前:     xxxxx.vercel-dns-017.com
```

```
Aliases:  dev.api.meap-app.com
名前:     xxxxx.up.railway.app
```

```powershell
curl.exe -s -o NUL -w "%{http_code}`n" https://dev.meap-app.com/
curl.exe -s -o NUL -w "%{http_code}`n" https://dev.api.meap-app.com/up
```

`200` なら DNS とサーバーまで到達しています。

### ダッシュボード

- **Vercel** → プロジェクト → Settings → Domains（`meap-app.com` / `dev.meap-app.com` が Verified か）
- **Railway** → サービス → Settings → Networking / Custom Domain（`api.meap-app.com` / `dev.api.meap-app.com` が紐付いているか）
- **DNS 管理**（Cloudflare 等）に CNAME があるか

## ステージングの保護

`dev.meap-app.com` はカスタムドメインなので、URL を知っていれば開けます。**Basic 認証はソースから削除済み**です。検索に載せない手段は **noindex**（`NEXT_PUBLIC_NOINDEX`）を使います。

| 手段                 | 検索防止               | ブラウザ E2E | 備考                         |
| -------------------- | ---------------------- | ------------ | ---------------------------- |
| `dev.` + リンクなし  | 偶然発見は少ない       | 影響なし     | 公開前の試運転場として許容   |
| フロントの `noindex` | インデックス防止に向く | 影響なし     | ステージング・公開前本番向け |

### Basic 認証の廃止

以前は Railway API と Vercel SSR（`apiClient`）で Basic 認証を使っていました。ブラウザからの API 呼び出しが 401 になり、Google OAuth のコールバックでも問題が出やすかったため、**アプリコードから Basic 認証を削除**しました。

コードはもう `BASIC_AUTH_*` を読みません。ダッシュボードに変数が残っていても動作には影響しませんが、混乱を避けるため **Railway / Vercel からも削除**してください。

### Railway / Vercel から `BASIC_AUTH_*` を削除する手順

対象変数（両プラットフォーム共通の名前）:

| 変数名                | 設定していた場所                   |
| --------------------- | ---------------------------------- |
| `BASIC_AUTH_USER`     | Railway（API）、Vercel（フロント） |
| `BASIC_AUTH_PASSWORD` | Railway（API）、Vercel（フロント） |

#### Railway（API）

ステージング（`dev.api.meap-app.com`）と本番 API（`api.meap-app.com`）の **両サービス** で実施します。

1. [Railway](https://railway.app/) にログインし、プロジェクトを開く
2. API サービスを選択 → **Variables** タブ
3. `BASIC_AUTH_USER` と `BASIC_AUTH_PASSWORD` を **Delete**（値を空文字にするのではなく、変数ごと削除）
4. 変数変更で自動再デプロイされる。完了後、401 が返らないことを確認:

```powershell
curl.exe -s -o NUL -w "%{http_code}`n" https://dev.api.meap-app.com/up
curl.exe -s -o NUL -w "%{http_code}`n" https://api.meap-app.com/up
```

`200` なら Basic 認証は無効です（以前は 401 になることがありました）。

#### Vercel（フロント）

ステージング（`dev.meap-app.com`）と本番（`meap-app.com`）の **各 Environment**（Production / Preview 等）で、該当変数があれば削除します。

1. [Vercel](https://vercel.com/) → プロジェクト → **Settings** → **Environment Variables**
2. `BASIC_AUTH_USER` / `BASIC_AUTH_PASSWORD` を検索し、紐づく Environment ごとに **Delete**
3. **Deployments** → 対象環境の最新デプロイ → **Redeploy**（環境変数の削除は再デプロイまで反映されない）

削除後、`dev.meap-app.com` でログイン〜OAuth までブラウザ E2E が通ることを確認します。

### noindex（`NEXT_PUBLIC_NOINDEX`）

環境変数 **`NEXT_PUBLIC_NOINDEX`** でインデックス禁止を ON/OFF します。`true` または `1` のとき noindex（`<meta name="robots">` と `/robots.txt` の `Disallow: /`）。未設定またはそれ以外は index 許可です。

**方針:**

- **ステージング**（`dev.meap-app.com`）は常に `true` にする
- **本番**（`meap-app.com`）は **公開日まで** `true` にしておき、公開日に OFF に切り替える。DNS は向いているため、非公開状態は noindex で維持する

| 環境                                   | 推奨値                   | 備考                                        |
| -------------------------------------- | ------------------------ | ------------------------------------------- |
| ローカル                               | 未設定（index 許可）     | 開発用                                      |
| Vercel ステージング（`dev.meap-app.com`） | **`true`（固定）**       | カスタムドメインのため常時 noindex          |
| Vercel 本番（公開前）                  | **`true`（推奨）**       | DNS 済みのため、最終確認中も noindex を維持 |
| Vercel 本番（公開日）                  | 変数を削除するか `false` | 変更後 **Redeploy** が必要                  |

Vercel での設定例:

1. **Settings** → **Environment Variables** → `NEXT_PUBLIC_NOINDEX` を追加
2. ステージング用 Environment（Preview 等）には Value `true`
3. 本番 Production は公開前 `true`、公開日に削除または `false` に変更
4. **Deployments** → **Redeploy**（環境変数の変更は再デプロイまで反映されない）

公開日のチェックリスト（[リリース日に同時に行うこと](#リリース日に同時に行うこと)）に noindex 解除を含めてください。

## 本番テストの進め方

公開前は **Vercel / Railway の用意ドメイン**（または `dev.*`）で E2E を完走し、公開日に noindex 解除・PAY.JP live・告知を行います。本番ドメインの DNS 切替は不要です（設定済み）。課金の通し確認は [PAY.JP 課金 E2E 手順](PAY.JP_課金_E2E_手順.md) を参照してください。

```
公開前
  Railway  → xxxxx.up.railway.app（または dev.api.meap-app.com / api.meap-app.com）
  Vercel   → xxxxx.vercel.app（または dev.meap-app.com / meap-app.com）
  ↓ メール・OAuth・課金・招待・AI を確認（本番は noindex 中でも可）
公開時
  NEXT_PUBLIC_NOINDEX を解除して Redeploy
  PAY.JP live モード・本番 Webhook（`/payjp/webhook`）
  LP・SNS から https://meap-app.com を案内
```

### noindex が必要か

| 環境                 | ドメイン例                          | noindex                                           |
| -------------------- | ----------------------------------- | ------------------------------------------------- |
| 本番テスト（非公開） | `*.vercel.app` / `*.up.railway.app` | **不要**。リンクしなければ十分                    |
| ステージング         | `dev.meap-app.com`                     | **あると安心**（カスタムドメイン）                |
| 本番公開前           | `meap-app.com`                      | **必須**（DNS 済みのため noindex で非公開を維持） |
| 本番公開後           | `meap-app.com`                      | 公開日に解除                                      |

プラットフォーム標準ドメインは推測しにくく、`meap-app.com` とは別物です。SNS や GitHub に貼るとインデックスされる可能性はあります。

本番ドメインは DNS 済みのため、公開前は `NEXT_PUBLIC_NOINDEX=true` で検索エンジンに載らないようにします。公開日に解除すれば `/sitemap.xml` と `/robots.txt` が index 許可に切り替わります。

## リリース日に同時に行うこと

次を同じ日に揃えると、デプロイと公開が混同しにくくなります。

1. Vercel 本番の `NEXT_PUBLIC_NOINDEX` を削除するか `false` にして **Redeploy**
2. PAY.JP live モード・live API キー・本番 Webhook（`https://api.meap-app.com/payjp/webhook`。手順は [PAY.JP 課金・Webhook 手順](PAY.JP_課金_Webhook_手順.md)）
3. live で少額決済 1 件（例: ライトパック）→ Webhook 200 とプラン・残数反映を確認（[PAY.JP 課金 E2E 手順](PAY.JP_課金_E2E_手順.md)）
4. LP・SNS から `https://meap-app.com` の案内開始

未設定の場合のみ、あわせて次も確認してください。

- Vercel 本番の `NEXT_PUBLIC_BACKEND_URL` が `https://api.meap-app.com`
- Railway の `APP_URL` / `FRONTEND_URL` / `SANCTUM_STATEFUL_DOMAINS` が本番ドメイン

## ステージング E2E の再実行

API 疎通は次で確認します。

```powershell
curl.exe -s -o NUL -w "%{http_code}`n" https://dev.api.meap-app.com/up
curl.exe -s -o NUL -w "%{http_code}`n" https://api.meap-app.com/up
```

メール送信失敗やメール未認証（409）があると、課金・招待・AI の完走はできません。Railway / Vercel から `BASIC_AUTH_*` を削除したあと、ブラウザでログインから通し確認します。課金は PAY.JP テストカードで [PAY.JP 課金 E2E 手順](PAY.JP_課金_E2E_手順.md) に沿って確認してください。本番ドメイン（`meap-app.com`）でも noindex 中に同様の確認が可能です。
