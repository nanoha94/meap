# ステージングと本番公開の方針

デプロイと一般公開は別です。この文書は、ステージングの保護、本番テストの進め方、DNS / Google 検索の扱いをまとめます。

関連:

- [Railway 本番マイグレーション手順](Railway_本番マイグレーション手順.md)
- [Stripe 課金・Webhook 手順](Stripe_課金_Webhook_手順.md)

---

## デプロイとリリース

| 用語 | 意味 |
| --- | --- |
| **デプロイ** | コードをサーバーに載せる。URL が存在する状態になる |
| **リリース** | 一般ユーザーが使える状態にする（本番ドメインの DNS、告知、Stripe live、noindex 解除など） |

本番 API を Railway に載せても、次をしなければ表向きのリリースにはなりません。

1. `meap.blog` / `api.meap.blog` の DNS を向ける
2. Vercel 本番の `NEXT_PUBLIC_BACKEND_URL` を本番 API に切り替える
3. 本番の `NEXT_PUBLIC_NOINDEX` を解除し、検索インデックスを許可する
4. Stripe を live モードにする
5. LP や SNS から `meap.blog` を案内する

---

## 環境の役割

| 環境 | URL の例 | 役割 |
| --- | --- | --- |
| ステージング | `dev.meap.blog` / `dev.api.meap.blog` | 本番相当の E2E。カスタムドメインあり |
| 本番テスト（非公開） | `*.vercel.app` / `*.up.railway.app` | 公開前の通し確認。本番ブランドとしては出さない |
| 本番（公開） | `meap.blog` / `api.meap.blog` | 一般公開用。DNS を向ける日をリリース日とみなす |

ステージングのカスタムドメインは **既に DNS 済み** です。Google 検索に出ないのは DNS 未設定ではなく、未リンク・未クロールが主因です。

---

## DNS の確認方法

DNS 設定済みとは、ホスト名が Vercel / Railway に解決され、HTTPS で応答が返ることです。未設定なら名前解決に失敗するか、別先を向いて 404 などになります。

### ターミナル

```powershell
nslookup dev.meap.blog
nslookup dev.api.meap.blog
```

名前（`Aliases`）と CNAME / IP が返れば DNS は設定済みです。

確認時の例:

```
Aliases:  dev.meap.blog
名前:     xxxxx.vercel-dns-017.com
```

```
Aliases:  dev.api.meap.blog
名前:     xxxxx.up.railway.app
```

```powershell
curl.exe -s -o NUL -w "%{http_code}`n" https://dev.meap.blog/
curl.exe -s -o NUL -w "%{http_code}`n" https://dev.api.meap.blog/up
```

`200` なら DNS とサーバーまで到達しています。

### ダッシュボード

- **Vercel** → プロジェクト → Settings → Domains（`dev.meap.blog` が Verified か）
- **Railway** → サービス → Settings → Networking / Custom Domain（`dev.api.meap.blog` が紐付いているか）
- **DNS 管理**（Cloudflare 等）に CNAME があるか

## ステージングの保護

`dev.meap.blog` はカスタムドメインなので、URL を知っていれば開けます。**Basic 認証はソースから削除済み**です。検索に載せない手段は **noindex**（`NEXT_PUBLIC_NOINDEX`）を使います。

| 手段 | 検索防止 | ブラウザ E2E | 備考 |
| --- | --- | --- | --- |
| `dev.` + リンクなし | 偶然発見は少ない | 影響なし | 公開前の試運転場として許容 |
| フロントの `noindex` | インデックス防止に向く | 影響なし | ステージング・公開前本番向け |

### Basic 認証の廃止

以前は Railway API と Vercel SSR（`apiClient`）で Basic 認証を使っていました。ブラウザからの API 呼び出しが 401 になり、Google OAuth のコールバックでも問題が出やすかったため、**アプリコードから Basic 認証を削除**しました。

コードはもう `BASIC_AUTH_*` を読みません。ダッシュボードに変数が残っていても動作には影響しませんが、混乱を避けるため **Railway / Vercel からも削除**してください。

### Railway / Vercel から `BASIC_AUTH_*` を削除する手順

対象変数（両プラットフォーム共通の名前）:

| 変数名 | 設定していた場所 |
| --- | --- |
| `BASIC_AUTH_USER` | Railway（API）、Vercel（フロント） |
| `BASIC_AUTH_PASSWORD` | Railway（API）、Vercel（フロント） |

#### Railway（API）

ステージング（`dev.api.meap.blog`）と本番 API の **両サービス** で実施します。

1. [Railway](https://railway.app/) にログインし、プロジェクトを開く
2. API サービスを選択 → **Variables** タブ
3. `BASIC_AUTH_USER` と `BASIC_AUTH_PASSWORD` を **Delete**（値を空文字にするのではなく、変数ごと削除）
4. 変数変更で自動再デプロイされる。完了後、401 が返らないことを確認:

```powershell
curl.exe -s -o NUL -w "%{http_code}`n" https://dev.api.meap.blog/up
```

`200` なら Basic 認証は無効です（以前は 401 になることがありました）。

#### Vercel（フロント）

ステージング（`dev.meap.blog`）と本番の **各 Environment**（Production / Preview 等）で、該当変数があれば削除します。

1. [Vercel](https://vercel.com/) → プロジェクト → **Settings** → **Environment Variables**
2. `BASIC_AUTH_USER` / `BASIC_AUTH_PASSWORD` を検索し、紐づく Environment ごとに **Delete**
3. **Deployments** → 対象環境の最新デプロイ → **Redeploy**（環境変数の削除は再デプロイまで反映されない）

削除後、`dev.meap.blog` でログイン〜OAuth までブラウザ E2E が通ることを確認します。

### noindex（`NEXT_PUBLIC_NOINDEX`）

環境変数 **`NEXT_PUBLIC_NOINDEX`** でインデックス禁止を ON/OFF します。`true` または `1` のとき noindex（`<meta name="robots">` と `/robots.txt` の `Disallow: /`）。未設定またはそれ以外は index 許可です。

**方針:**

- **ステージング**（`dev.meap.blog`）は常に `true` にする
- **本番**（`meap.blog`）は **公開日まで** `true` / 未設定（OFF）のどちらでもよい。DNS を向けたあと最終確認する間は `true` にしておき、公開日に OFF に切り替える

| 環境 | 推奨値 | 備考 |
| --- | --- | --- |
| ローカル | 未設定（index 許可） | 開発用 |
| Vercel ステージング（`dev.meap.blog`） | **`true`（固定）** | カスタムドメインのため常時 noindex |
| Vercel 本番（公開前） | `true` 推奨 | DNS 未設定なら OFF でも可。DNS 向け後の確認中は `true` |
| Vercel 本番（公開日） | 変数を削除するか `false` | 変更後 **Redeploy** が必要 |

Vercel での設定例:

1. **Settings** → **Environment Variables** → `NEXT_PUBLIC_NOINDEX` を追加
2. ステージング用 Environment（Preview 等）には Value `true`
3. 本番 Production は公開前 `true`、公開日に削除または `false` に変更
4. **Deployments** → **Redeploy**（環境変数の変更は再デプロイまで反映されない）

公開日のチェックリスト（[リリース日に同時に行うこと](#リリース日に同時に行うこと)）に noindex 解除を含めてください。

## 本番テストの進め方

公開前は **Vercel / Railway の用意ドメイン**（または `dev.*`）で E2E を完走し、公開日に本番ドメインへ置き換えます。

```
公開前
  Railway  → xxxxx.up.railway.app（または dev.api.meap.blog）
  Vercel   → xxxxx.vercel.app（または dev.meap.blog）
  ↓ メール・OAuth・課金・招待・AI を確認
公開時
  meap.blog / api.meap.blog の DNS を向ける
  NEXT_PUBLIC_BACKEND_URL などを本番ドメインに切替
  noindex 解除・Stripe live・告知
```

### noindex が必要か

| 環境 | ドメイン例 | noindex |
| --- | --- | --- |
| 本番テスト（非公開） | `*.vercel.app` / `*.up.railway.app` | **不要**。リンクしなければ十分 |
| ステージング | `dev.meap.blog` | **あると安心**（カスタムドメイン） |
| 本番公開 | `meap.blog` | 公開前は noindex、公開日に解除 |

プラットフォーム標準ドメインは推測しにくく、`meap.blog` とは別物です。SNS や GitHub に貼るとインデックスされる可能性はあります。

`meap.blog` の DNS を向けた直後は公開スイッチになります。向けたまま最終確認する場合は、一時的に noindex または `robots.txt` の `Disallow: /` を入れて、公開日に外します。

---

## リリース日に同時に行うこと

次を同じ日に揃えると、デプロイと公開が混同しにくくなります。

1. `meap.blog` / `api.meap.blog` の DNS 切替（または noindex 解除）
2. Vercel 本番の `NEXT_PUBLIC_BACKEND_URL` を本番 API に
3. Railway の `APP_URL` / `FRONTEND_URL` / `SANCTUM_STATEFUL_DOMAINS` を本番ドメインに
4. Stripe live モードと本番 Webhook（手順は [Stripe 課金・Webhook 手順](Stripe_課金_Webhook_手順.md)）
5. LP・SNS からの案内開始

## ステージング E2E の再実行

API 側の疎通確認用スクリプト:

```bash
cd server
node scripts/staging-e2e-smoke.mjs
```

メール送信失敗やメール未認証（409）があると、課金 Checkout・招待・AI の完走はできません。Railway / Vercel から `BASIC_AUTH_*` を削除したあと、ブラウザでもログインから通し確認します。
